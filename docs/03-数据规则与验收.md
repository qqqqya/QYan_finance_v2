# 数据规则与验收

本文件为开发约束与验收依据，配合 `01-产品需求.md` 使用。以下是待实现、待执行的规则和测试，**不是已经通过的测试报告**。

## 1. 金额、时间和记录语义

| 项目 | 规则 |
|---|---|
| 金额 | 单币种 CNY；数据库与 JSON 使用整数“分”。例如 12.34 元保存为 1234，不用浮点数累计金额 |
| 输入 | 字符串解析为整数分；最多两位小数。资产/负债余额允许 0，收入/支出必须大于 0；方向由类型决定 |
| 范围 | 单笔/单个余额暂定不超过 9,999,999,999.99 元；汇总使用有溢出检查的 64 位整数，不受单笔上限限制；净资产及月结余允许为负 |
| 业务时间 | 保存用户填写的业务日期、时间；月份与图表按它分组。V1 不接受未来业务时间 |
| 系统时间 | createdAt、updatedAt、修改历史时间保存为 UTC 时间戳，不参与月份归属；编辑不改写 createdAt |
| 时区 | 首次使用保存设备时区为账本时区，恢复时保留。系统时区变动不自动搬移既有业务日期；V1 不提供历史数据时区换算 |
| 标识 | 各业务对象使用稳定 UUID；不要以名称、列表下标、语言文本或时间作为唯一 ID |
| 本地保存 | 业务数据存 SQLite；一次操作涉及的记录、修改历史和关联清理在同一事务提交，失败全部回滚 |
| 界面刷新 | 数据库为唯一事实来源，首页、明细与图表订阅查询结果；不在多个页面分别维护一份余额 |

### 余额记录是“余额快照”，不是收入/支出流水

例：10 月 1 日手动记录余额 1,000 元，10 月 10 日记录 1,200 元。

- 当前余额为 1,200 元，第二条变化额为 +200 元；不能相加得 2,200 元。
- 把第一条改为 900 元：当前余额仍为 1,200 元，第二条变化额重算为 +300 元。
- 删除 10 月 10 日记录：当前余额为 900 元；再删除剩余记录则为 0。
- 另一种操作：不删除记录，而是将改为 900 元的第一条时间改到 10 月 11 日，它成为最新记录，当前余额改为 900 元。
- 同一业务时刻存在多条记录时，按持久化的创建顺序 `orderKey` 排序，后创建者生效；编辑和导入不改变此顺序。
- 删除编辑历史只清除前后值的痕迹，不改变上述余额快照。

每条记录的变化额 = 本条余额 − 上一条余额；第一条以前值 0 计算。变化额是推导值，不能另存为需要手工维护的事实。

趋势金额仍按时点取最后已知余额。按用户在阶段 3 开始时的最新决定，显示采用记录时点等距排列、相邻点直线连接，不再画阶梯线；横轴注明记录顺序及业务日期，连线只示意变化，不表示记录之间的实际余额或等比例时间。首条前不编造曲线，不增加伪造的末尾记录；窗口起点可保留此前已知余额。同一时刻按 orderKey 取各项目最后余额并归并一个汇总点。按**当前存在且勾选的项目**回算，删除项目或改变汇总开关会重算整段趋势。资产构成按当前余额计算，零值不画扇区，总额为 0 时展示空状态。

独立收支项目按现存明细求和；月度账单按独立的账单表求和。两者与余额快照之间没有自动写入关系。

## 2. 最小数据结构

| 对象 | 必要内容 |
|---|---|
| Project | id、type（asset/liability/income_log/expense_log）、内置名称键或用户名称、分类、图标/颜色、是否参与对应汇总、排序 |
| BalanceRecord | id、projectId、balanceMinor、businessDate、businessTime、orderKey、备注；仅属于资产或负债项目 |
| ProjectEntry | id、projectId、amountMinor、业务日期/时间、备注；仅属于独立收支项目，方向继承项目类型 |
| Bill | id、income/expense、amountMinor、categoryId、业务日期/时间、备注；**没有 projectId/accountId** |
| Category | id、收入/支出方向、内置名称键或用户名称、排序、是否停用；项目分类可使用单独字典 |
| Memo | id、标题、正文、业务日期、标签 |
| EditHistory | id、entityType、entityId、changedAt、before、after；修改历史可删除，不用于重建当前业务记录 |
| Settings | 主题模式、语言模式、currency、账本时区；首页项目顺序保存于 Project |

业务对象统一保存 createdAt、updatedAt；修改历史自身使用 changedAt。总资产、当前余额、变化额、图表和月汇总均为推导结果，不作为可编辑字段。初始金额也通过余额记录表达，不再额外累加一次 openingBalance。

金额、日期、名称等修改保留前后差异；修改历史中的金额同样使用整数分。删除业务对象时清理其修改历史。删除分类前先处理账单引用；类别方向必须与账单方向一致。切换账单收入/支出时，必须重新选择适用分类。

## 3. 正式备份协议：finance-backup v1

文件名示例：`finance-backup_20261021_180000_v1.json`。使用 UTF-8、ISO 日期和稳定英文字段名，不随界面语言改变。数据库版本与备份协议版本分别管理。

| 顶层字段 | 内容 |
|---|---|
| format | 固定值 `finance-backup`，用于识别本应用文件 |
| schemaVersion | 整数，首版为 1；决定解析与迁移方式 |
| appVersion | 导出它的应用版本，仅供排查 |
| exportedAt | UTC 导出时间 |
| currency / timeZone | CNY / 账本时区 |
| data | projects、balanceRecords、projectEntries、bills、categories、memos、editHistory、settings |

导出包含全部业务数据和用户设置，保留 ID、orderKey、时间与字段类型；不包含统计缓存、应用内恢复副本或设备文件路径。删除过的内容不重新导出。导出时读取同一数据库快照，避免半新半旧。

导入顺序：

1. 先在临时区域解析，校验文件大小、格式标记、版本、必填字段、字段类型、整数精度、金额范围、有效日期和枚举。
2. 校验 ID 唯一、父子引用、项目类型、分类方向、排序字段和修改历史所属对象；头部币种/时区与设置一致。缺表、重复 ID、孤立记录等给出可理解的错误，不“猜着导入”。
3. 生成预览：备份时间、各类数量、汇总预览、主题语言是否一并恢复，并明确“将替换当前全部数据”。
4. 用户确认后先生成可恢复的当前数据副本，再在事务中整体替换；成功后刷新全部页面，失败恢复原状态。
5. 不支持的更高版本直接拒绝；旧版只有存在明确迁移器并测试通过时才允许导入。文件名不能充当格式校验。

恢复副本只保留最近一次成功覆盖前的数据，设置页可删除；恢复它也走校验、预览和确认，不把正在读取的副本覆盖掉。恢复出厂清除该副本。导入资源上限在阶段 4 依据目标设备验证并固定；本应用合法导出的文件必须处于可恢复范围，不能导出成功却拒绝恢复。超限文件给出提示，不尝试部分导入。

**往返一致性标准：导出 A → 空库恢复 → 导出 B，除导出时间及导出应用版本等元数据外，所有业务字段、ID、历史、排序和设置一致，所有重算结果一致。** 重复恢复同一备份数量不增加。旧版截图里的“JSON”不代表新旧协议天然兼容。

安卓通过系统文件选择器读写用户选定文件，按[Android 文档框架](https://developer.android.com/training/data-storage/shared/documents-files)处理 URI，不把它错误当作普通磁盘路径，也不申请全盘文件访问权限。

## 4. 必须执行的验收场景

历史需求日期只作为缺陷来源标签，不推断年份。T01–T24 是 V1 交付条件，按所属阶段执行，不要求每次小改都重跑全套。

| 编号 | 操作 | 预期结果 |
|---|---|---|
| T01 初始化 | 全新安装，并分别重启、后台恢复 | 默认项目全为 0；没有 10,000 等演示值或假趋势；空分类图不报错 |
| T02 模块独立 | 资产设为 1,000；账单新增/修改/删除支出；另建独立收入 | 资产始终 1,000；各模块只更新自己的统计 |
| T03 余额语义 | 执行本文件的 1,000→1,200 例子，改金额、改时间、删最新、删全部 | 分别得到规定结果；趋势与变化额一致，补录不覆盖较新余额 |
| T04 修改历史 | 修改金额、时间、备注，删除一条历史，再清空历史 | 可查看前后值及实际修改时间；删除历史不改变业务金额；重启后不复现 |
| T05 总资产 | 资产 1,000+2,000，负债 500；再切换计入开关、删除项目 | 总资产 3,000、负债 500、净资产 2,500；变动即重算，收入/支出项目不混入（0317） |
| T06 大数与输入 | 输入上限金额、0.01、超过两位小数、非法负数、超限值；检查大额汇总 | 合法金额精确；非法值提示；总资产完整显示，无截断或溢出（0317、0407） |
| T07 跨月补录 | 模拟 10 月 31 日，在 9 月点“记一笔”；另测闰年 2 月及跨年 | 默认 9 月 30 日；记录归所选月份；2 月正确处理 28/29 日（0407） |
| T08 跨月编辑 | 9 月支出 100 改成 10 月支出 150，再改收入并换分类 | 9 月归零，10 月对应收支正确；两月、年度与图表同步更新 |
| T09 收支图表 | 同月同时有收入、支出，切换两种图；编辑和删除最后一笔 | 图表与图例只展示所选方向；明细筛选一致；归零后显示空状态（0324） |
| T10 图例与趋势 | 多项目、多分类、长名称、零条/一条记录 | 名称、金额、占比可读；日期与金额轴可见；无除零、假曲线或负扇区（0317） |
| T11 项目排序删除 | 首页长按并移动；重启；进入详情删除一个默认项目及一个自建项目 | 长按不删除；排序保留；删除说明影响并确认；相关数据清理无孤立引用（0317） |
| T12 主题模式 | 浅色/深色/跟随系统分别切换系统主题，并新增项目 | 手动模式不受系统影响；跟随模式立即更新；新项目和图表一致；重启保持（0317） |
| T13 三语 | 简中、繁中、英文各走主要页面，检查长文案和确认框 | 默认文案、分类、备忘录入口均切换；用户自定义文字保持原样（0317） |
| T14 返回行为 | 详情左右边缘返回、系统返回键、普通横滑、返回手势取消、弹层、键盘、未保存表单 | 详情回上一层，非根页面不意外退桌面；取消不丢数据；首页返回遵循系统规则（0407） |
| T15 分类与备忘录 | 修改/停用已引用分类；搜索、编辑、删除备忘录 | 旧账单仍可显示；新记录不再选停用分类；备忘录不影响任何金额 |
| T16 备份往返 | 带三种语言文字、历史、排序、主题及所有数据类型导出并恢复 | 达到上述往返一致性；包括分、日期、标签及设置的完整恢复 |
| T17 重复与坏文件 | 重复恢复；缺字段、错类型、重复 ID、坏引用、超限金额、损坏 JSON、不支持版本 | 重复恢复不叠加；其他情况拒绝并解释，原数据完全不变 |
| T18 文件失败 | 取消选择、拒绝访问、空间不足、导出写入失败、恢复副本失败 | 不虚报成功；不覆盖原库；再次进入仍正常；文件 URI 读写可用 |
| T19 事务中断 | 在业务保存、导入替换、恢复出厂过程中模拟失败或杀进程 | 数据保持修改前或完整修改后状态，绝不出现半更新；重启可用 |
| T20 恢复出厂 | 有数据时先取消，再确认清空；检查私有恢复副本和外部导出文件 | 取消无变化；确认后全部归默认且金额为 0；私有副本清除、外部文件保留 |
| T21 持久化 | 增删改后杀进程再启动；连续快速点击保存 | 已提交内容、设置和排序保留；一次提交只产生一条记录 |
| T22 屏幕与系统 | 360/480dp 实测，320dp/横屏溢出检查；100%/150%/200% 字号、深浅色、键盘和挖孔 | 可滚动、可操作；金额/按钮不遮挡；卡片可降为单列；不抢系统手势区 |
| T23 数据量 | 50 个项目、累计 10,000 条记录，滚动、切月、统计、备份 | 无 ANR/崩溃；明细分页或懒加载。固定测试设备与数据，目标首页和切月常规操作 1 秒内完成 |
| T24 升级 | 用已发布测试版数据安装新版；执行数据库迁移与再次导出 | 不丢记录、设置、精度及历史；迁移失败有恢复路径，不能默认删库重建 |

自动化优先覆盖金额、时间归属、快照排序、模块独立、事务与备份往返；真实设备重点验证返回、文件读写、键盘、长金额和布局。记录测试环境、步骤、预期、实际与证据；没有设备或环境时标记未验证，不推定通过。
