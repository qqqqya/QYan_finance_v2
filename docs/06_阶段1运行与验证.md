## 1. 已实现范围

- Android 优先的 Flutter 工程，包名 `com.example.finance_app`，版本 `0.1.0+1`，最低 Android 10 / API 29。
- 首页：整行资产总览、总负债/净资产、默认九项目的只读卡片；数值从数据库查询计算。所有初始金额均为 0，不创建虚假收支记录。
- 设置：跟随系统/浅色/深色，跟随系统/简中/繁中/English；保存到 SQLite，语言和主题即时更新。设置页可从系统返回上一层。
- SQLite/Drift：8 张表，事务、外键、类型约束、业务索引和删除后的历史清理触发器；数据库版本 1，结构基线保存于 `drift_schemas/drift_schema_v1.json`。
- 金额：整数分解析和完整格式化，单笔范围校验，64 位汇总溢出检查。日期：严格日历校验、业务时区、未来时间校验、跨月默认日期。余额：按业务时间和 orderKey 排序，不累加快照。
- 正式备份字段、JSON Schema、最小样例；详见 `07_备份协议v1.md`。

当前没有完整项目编辑、记账、图表、备忘录、导入导出或恢复出厂界面。首页的卡片为真实数据的只读展示，未放置这些尚未实现功能的空按钮。

## 3. 运行、测试、构建

在 `D:\Finance` 的 PowerShell 7 中执行（本机已具备；备份检查使用其 Test-Json）。冷环境先按文档 04 的软件清单准备工具；本机已下载的版本如上。完整原始规划和截图保留在 docs/png。

```powershell
# 还原锁定的项目依赖并生成源码
.\scripts\flutter.ps1 pub get
.\scripts\dart.ps1 run build_runner build
.\scripts\flutter.ps1 gen-l10n

# 启动已配置的项目模拟器（后台验证可加 -Headless）
.\scripts\start-emulator.ps1

# 查看设备，再选择实际 Android 设备 ID；本项目模拟器为 emulator-5560
.\scripts\flutter.ps1 devices
.\scripts\flutter.ps1 run -d emulator-5560

# 静态检查、单元/数据库/组件测试及备份协议检查
.\scripts\check.ps1

# Android 冒烟测试，需要已启动的 Android 设备
.\scripts\flutter.ps1 test integration_test/app_smoke_test.dart -d emulator-5560 --no-pub

# 构建调试包；生成后位于 build/app/outputs/flutter-apk/app-debug.apk
.\scripts\flutter.ps1 build apk --debug

# 在已安装正常入口 APK 的项目模拟器上执行原生检查；会切换测试设备的语言/主题
.\scripts\verify-android.ps1
```

本机命令环境由 `scripts/environment.ps1` 配置，测试临时目录也放入项目内，避免沙箱临时路径造成的文件访问失败。外部文件读写和本地测试端口若受执行环境限制，应使用允许这些能力的运行环境，不以跳过测试代替验证。

数据库位于应用私有 Support 目录的 `finance.sqlite`。关闭或重启应用不会重新播种已有数据库；卸载会删除私有数据。迁移目前只有 v1 基线，未知版本升级会明确失败，不删除旧库重新初始化；未来增加版本时必须补明确迁移及其测试。

本机 AVD 使用 Pixel 6 配置、1080×2400、420 dpi、2 GB 内存和 4 核。首次系统镜像下载较慢，下载后已比对 Google 仓库公布的 SHA-1 `829c076e8ff448a336097ae25a355b495ba36e2c`；Gradle 精简包也比对官方 SHA-256。新电脑应通过 Android Studio 的 SDK Manager 安装 API 36 default x86_64 镜像，再在 Device Manager 创建名为 `Finance_API_36` 的设备，并配置 `ANDROID_AVD_HOME` 为本工程 `.tooling/avd`。`start-emulator.ps1` 只启动已有设备，不自动下载软件。

本次验证使用 `start-emulator.ps1 -Headless`。需要查看模拟器窗口时，先 `. .\scripts\environment.ps1`，执行 `& "$env:ANDROID_HOME\platform-tools\adb.exe" -s emulator-5560 emu kill`，再运行不带 `-Headless` 的启动脚本。停止后台设备后再启动，避免同一 AVD 的实例冲突。原生检查前，测试设备需为系统手势导航模式；本次实际命令为 `adb -s emulator-5560 shell cmd overlay enable-exclusive --category com.android.internal.systemui.navbar.gestural`，核对 navigation_mode 为 2 后再开始测试。

直接安装交付包：

```powershell
. .\scripts\environment.ps1
& "$env:ANDROID_HOME\platform-tools\adb.exe" -s emulator-5560 install -r .\artifacts\finance-stage1-debug.apk
& "$env:ANDROID_HOME\platform-tools\adb.exe" -s emulator-5560 shell am start -W -n com.example.finance_app/.MainActivity
```

交付包含 ARM32 / ARM64 / x86_64，约 203 MiB，正常入口为 `lib/main.dart`，没有把集成测试入口作为交付包。文件大小与 SHA-256 记录在 `artifacts/verification/stage1-apk-manifest.json`；应用 ID 为开发占位，使用调试签名，正式发布前再确定包名、签名和包体优化。
