## 6. 数据实体与备份字段设计

沿用文档 03 的 8 类对象；这里补充准备阶段的字段约定，正式校验器在阶段 1 定义、阶段 4 实现备份流程。

| 对象 | 计划字段 |
|---|---|
| Project | id、type、nameKey/customName、categoryKey/customCategory、iconKey、colorKey、includeInSummary、sortOrder、note、createdAt、updatedAt |
| BalanceRecord | id、projectId、balanceMinor、businessDate、businessTime、orderKey、note、createdAt、updatedAt |
| ProjectEntry | id、projectId、amountMinor、businessDate、businessTime、note、createdAt、updatedAt |
| Bill | id、type、amountMinor、categoryId、businessDate、businessTime、note、createdAt、updatedAt；没有 projectId/accountId |
| Category | id、type、nameKey/customName、sortOrder、isActive、createdAt、updatedAt |
| Memo | id、title、body、businessDate、tags、createdAt、updatedAt；tags 先用字符串列表，不新增标签管理体系 |
| EditHistory | id、entityType、entityId、changedAt、before、after；保存当次改动字段，不能充当重建当前值的数据源 |
| Settings | themeMode、languageMode、currency、timeZone；单个设置对象，与业务库事务一起备份恢复 |

`businessDate` 为 YYYY-MM-DD，`businessTime` 为 HH:mm（账本当地时间）；createdAt/updatedAt/changedAt 为 UTC ISO 8601。业务时间只在用户编辑时改变，不随设备时区重写。nameKey 与 customName 的优先规则为：用户改名后显示 customName，否则按内置键翻译；不会翻译用户输入。

资产和负债按（businessDate、businessTime、orderKey）取最后一条，orderKey 在同项目内唯一且不因编辑/导入重排。独立收支累加现存明细，账单按业务月份独立聚合；所有总额、图表点及变化额为推导结果。默认资产/负债可用一条金额 0 的初始快照，独立收支和账单不创建 0 元流水。

正式备份顶层为 format、schemaVersion、appVersion、exportedAt、currency、timeZone、data；data 内集合与文档 03 一致。以下仅是**字段结构示意**，不是已导出的文件，也不是默认项目模板：

```json
{
  "format": "finance-backup",
  "schemaVersion": 1,
  "appVersion": "0.1.0",
  "exportedAt": "2026-10-21T00:00:00Z",
  "currency": "CNY",
  "timeZone": "Asia/Shanghai",
  "data": {
    "projects": [],
    "balanceRecords": [],
    "projectEntries": [],
    "bills": [],
    "categories": [],
    "memos": [],
    "editHistory": [],
    "settings": {
      "themeMode": "system",
      "languageMode": "system",
      "currency": "CNY",
      "timeZone": "Asia/Shanghai"
    }
  }
}
```

拟定主题枚举 system/light/dark，语言枚举 system/zh-Hans/zh-Hant/en。金额严格 JSON 整数分；源数据保留 UUID、时间、排序和可见修改历史。删除记录后的历史也清理，内部恢复副本不递归放进备份。

恢复只做完整替换：校验及预览 → 确认 → 保存恢复副本 → 数据库事务替换 → 成功后刷新。系统文件副本与数据库事务不是同一原子事务，需按顺序保留旧库并验证副本可读；失败/杀进程时不允许先清库再补救。自家导出内容必须能重新恢复，具体内存/文件上限在阶段 4 测量后固定。
