# 14 · 持久签名与安装

适用：0.5.1+6，沿用阶段 5 原持久密钥及调试签名。当前安装包实测以文档 16 为准，历史阶段 5 见 13；本文不代表真机验收通过。

## 包的选择

| 包 | 用途 |
|---|---|
| finance-0.5.1-ide-debug.apk | 与本机 Android Studio 已有调试签名一致，现有模拟器/调试版更新优先用它；同包名、同签名覆盖保留数据 |
| finance-0.5.1-debug.apk | 与旧脚本交付调试签名一致，供原脚本版本覆盖更新 |
| finance-0.5.1-release.apk | 用本项目持久正式密钥签名的 release 测试候选；适合首次安装及后续沿用同一正式签名的更新，尚需真机验收 |

包名继续是 com.example.finance_app，最低 Android 10 / API 29。没有自动发布应用商店。版本、证书指纹、SHA-256、ABI、构建和安装结果在文档 16 和 refinement-apk-manifest.json 中记录。

## 从已有调试版更新

保持同一签名，直接覆盖安装，不要求每次导入导出。例如在 D:\Finance 执行：

```powershell
.\scripts\install-android.ps1 -Device <adb设备ID> -Apk artifacts/finance-0.5.1-ide-debug.apk -Launch
```

设备授权、USB 调试和 ADB 查看方法见文档 10。签名/版本冲突时停止安装，检查实际版本及对应包；不能以自动卸载/清库处理。

正式密钥与上述调试签名不同，正式候选不能直接覆盖调试版。这是 Android 签名机制的约束。如果以后决定切换正式签名，应先导出完整备份到外部位置并留存一份独立副本，核对文件/预览后，再由用户执行卸载调试版、安装正式候选及导入恢复。卸载清除私有数据库与恢复副本，因此不能先卸载再寻找备份。本次不对用户设备自动执行该迁移。

## 长期保留密钥

- 本地目录 D:\Finance\.signing，内含 finance-release.p12 和 keystore.properties。密码随机生成，仅保存在此私有目录，不打印、不写入源码或普通交付报告。
- 目录限制为当前 Windows 用户及 SYSTEM 访问；整个目录及 p12 均加入 .gitignore。不要把密钥或密码放进财务备份 JSON、截图、聊天记录、APK 或 Git。
- **请将整个 .signing 目录单独备份到自己控制的离线位置。** Git/源码/APK 不包含私钥；仅靠它们无法恢复签名。未自动将密钥上传或复制到其他路径。
- prepare-release-signing.ps1 默认只保留现有密钥，缺失即停止并要求从备份恢复。只有尚未交付正式签名的全新项目，才允许显式 -CreateNew 首次创建；已有 release manifest 时仍拒绝另建。部分文件缺失也停止。后续所有正式版本继续使用这份密钥，克隆源码或清理工具目录不能成为自动换签名的理由。
- app/build.gradle.kts 对 release 读取本地配置；缺失时构建明确失败，不能悄悄改用 debug 签名。调试构建不要求读取密钥。

构建命令（顺序执行，不并行运行 Flutter 测试和 APK 构建，避免生成的插件注册文件被互相改写）：

```powershell
.\scripts\prepare-release-signing.ps1
.\scripts\check.ps1
.\scripts\flutter.ps1 build apk --debug
.\scripts\flutter.ps1 build apk --release
```

prepare-release-signing 使用现有 JDK 的 keytool，没有新增工具安装。首次构建若缺已有框架的编译组件，按实际构建日志处理，不更改项目签名。签名与更新机制参考 [Android 官方说明](https://developer.android.com/studio/publish/app-signing) 和 [Flutter Android 交付文档](https://docs.flutter.dev/deployment/android)。

当前 Flutter SDK 在 debug/release 切换时需要正常生成对应的原生插件注册文件，因此这里不使用 --no-pub；保留 pubspec.lock，不执行依赖升级。不手工删除生成文件中的测试插件或失败测试来绕过编译。

## 备份兼容与卸载边界

财务备份不依赖 APK 签名。v0.0/v1/v2 导入、覆盖确认与恢复副本方法见文档 12、backup-format.md。同签名普通升级保留本机数据；跨签名或换机的人工迁移需要外部备份。备份格式版本、软件版本、数据库版本分别维护，不能随意换字段或清库“修复”升级。
