# 个人财务管理 App：产品需求

版本：规划稿 v1.1 · 2026-10-21 · 已完成阶段 0 核对，尚未开始应用开发。

建议先只审阅本文件；`02-开发阶段与AI提示词.md` 供后续分阶段开发时复制使用，`03-数据规则与验收.md` 主要交给 AI 实现和测试。

## 1. 产品定位与范围

面向个人的本地财务管理工具：手动维护资产与负债、记录月度收支、保存理财想法。先交付可长期使用的 Android 版本，之后再适配 iOS。

**用户已确认：月度账单与资产余额完全独立，余额由用户手动维护。** 记账、修改账单、删除账单都不能自动改变资产；调整资产也不能自动生成账单。两者统计不相等是正常情况。

用户本次明确：没有旧源码，从零创建工程；月度账单、独立收支、资产互不自动联动；所有初始化金额为 0。阶段 0 只核对和规划，不安装软件、不创建应用工程。

| 阶段 | 范围 |
|---|---|
| V1 必须完成 | 首页、资产/负债项目、独立收支项目、月度账单及年度汇总、理财备忘录、三语、三种主题模式、完整备份恢复、恢复出厂、安卓适配 |
| V1.1 再评估 | CSV 账单交换、旧文件迁移、搜索增强、预算、提醒、应用锁、加密备份、自定义初始化模板 |
| 后续 iOS | 在安卓验收通过后，处理 iOS 导航、文件选择、布局、签名及真机测试 |
| 当前不做 | 银行/支付平台自动同步、云账号与多端同步、行情抓取、自动收益计算、投资建议、家庭共享 |

V1 默认离线、无需登录、单币种人民币；语言切换不改变币种。“小组件”指 App 内的项目卡片，不包含安卓桌面 Widget。

- 恢复出厂使用系统默认项目模板，金额归零；不恢复某次使用时的旧余额。首次安装金额为 0 已是用户明确约束。

## 3. 首页与界面方向

视觉以简约、留白、清晰层级为主：浅灰背景、圆角卡片、轻阴影、统一字体，深色主题独立设计。采用类似苹果产品的简洁视觉，同时遵守 Android 返回与文件操作习惯。

建议首页顺序：

```text
设置                  财管                  ＋
┌──────── 总资产：完整金额，独占一行 ────────┐
│             总负债 / 净资产              │
└─────────────────────────────────────────┘
          月度账单        理财备忘录
        项目卡片网格：资产、负债、独立收支
```

- 普通卡片默认双列；窄屏或大字号改为单列。总资产始终占满可用内容宽度，不要求手机横屏。
- 首页长按只进入拖动排序，松手后持久化。删除项目只在项目详情页操作。
- 卡片名称可以换行；金额完整可读，不用省略号，不以“万 / 亿”的缩写替代唯一金额展示。
- 默认提供招商银行、交通银行、支付宝、现金、基金、理财产品、负债、大额收入、大额支出；普通默认项目和自建项目都可编辑、删除。总览和功能入口不作为普通项目删除。
- 固定色义：收入绿、支出红，资产用中性色；同时提供文字和正负号，不只依靠颜色表达。
- 表单支持数字键盘、字段校验、键盘避让、防重复提交。错误提示说明哪个字段有问题，不只显示“操作失败”。

## 4. 项目与总资产

### 4.1 四种项目类型

| 类型 | 输入与卡片金额 | 汇总规则 |
|---|---|---|
| 资产 | 手动记录某时刻余额；卡片显示最新有效余额 | 可选择“计入总资产”，默认开启 |
| 负债 | 手动记录某时刻尚欠金额；用正数表示欠款 | 可选择“计入总负债”，默认开启 |
| 独立收入 | 逐笔记录收入；卡片显示累计金额 | 不计入资产或月度账单 |
| 独立支出 | 逐笔记录支出；卡片显示累计金额 | 不计入资产或月度账单 |

新建字段：名称、类型、分类、图标/预设颜色；资产与负债可输入初始金额及时间，默认 0。独立收支从空记录开始，不能凭空设置累计金额。项目有记录后不允许直接切换类型，以免改变原有金额含义。

总资产 = 所有勾选资产项目的最新余额之和；总负债 = 所有勾选负债项目的最新余额之和；净资产 = 总资产 − 总负债。总资产不是净资产，独立收支项目不能重复计入。

### 4.2 资产、负债详情

- 显示名称、当前金额、趋势和余额记录。支持改名、分类、图标、汇总开关、备注及项目删除。
- “更新余额”填写**更新后的实际余额**、业务时间、备注；每次保存产生一条余额记录。
- 余额记录可修改时间、金额、备注，也可删除。业务时间表示余额所属时间，系统另外保存创建时间、最后修改时间。
- 当前余额取业务时间最新的记录；补录更早的余额不覆盖较新的余额。删除最新记录回到上一条；删光后为 0。完整例子见文档 03。
- 列表可显示相对上一条的变化额，但不能将多个余额相加。基金等按用户手动填写的当前价值管理，不自动拉取行情。

### 4.3 独立收支详情

每笔填写金额、时间、备注，可增删改；详情默认显示全部记录并可按月份筛选。累计值由现存记录求和，修改、删除后同步刷新。与月度账单重复输入同一事项时，系统仍视作两个独立记录，不自动同步或去重。

### 4.4 总资产详情与图表

- 资产构成：仅统计勾选的资产项目，图例同时显示名称、金额、占比；负债另外展示。
- 趋势：按手动余额记录回算，支持近 30 天 / 近 12 个月；无记录的时间不编造增长曲线。
- 零金额显示空状态；单个数据点显示点和金额。图例可滚动、可换行，趋势包含日期和金额坐标。
- 所有汇总、图表、详情使用同一套计算规则；数据保存成功后即更新，不能依赖重启或反复进入页面。

## 5. 月度账单

- 支持前后月份和年月选择器，默认当月；V1 不录入未来交易。保留页面当前选定月份，返回详情后不跳回当月。
- “记一笔”包含收入/支出、金额、分类、业务日期与时间、备注；**不设置资产账户关联字段**。
- 从历史月份新增时，默认日期必须在该月份内。例如当前 10 月 31 日，在 9 月点击记账，默认 9 月 30 日。当月默认今天。
- 用户主动改到其他月份时可保存，并提示“已记入 YYYY 年 MM 月”；当前页面保持原选月份，提供查看目标月份入口。
- 月汇总显示收入、支出、结余；结余 = 收入 − 支出。按业务日期归属月份，绝不能使用创建时间统计。
- 分类图默认展示支出，明细默认“全部”；点击“收入 / 支出”切换后，分类图与明细同步切换到对应方向。明细可单独切回“全部”，顶部两项汇总始终展示完整月数据。
- 明细支持编辑类型、金额、日期、分类、备注和删除；跨月修改后同时更新两个受影响月份、年度统计及图表。
- 内置常见分类：工资、奖金、其他收入；餐饮、交通、购物、住房、医疗、其他支出。支持新增、改名和停用分类；被引用分类不直接删除，可先迁移记录到其他分类。
- 年度统计为所选年份 12 个月的收入、支出、结余及图表；无记录月份为 0。

## 6. 理财备忘录与修改历史

备忘录字段：标题、正文、业务日期、标签；支持新增、编辑、删除，按日期排序，可按关键词和标签筛选。它是想法记录，不计入任何金额统计。

所有可编辑的金额记录以及备忘录，提供“修改历史”：记录修改时间、修改前后字段。用户能够删除单条历史或清空该记录的修改历史。

必须区分两类删除：

- **删除业务记录**：删除余额记录、收支明细或备忘录本身，相关统计随之重算。
- **删除修改历史**：仅清除编辑痕迹，不删除当前业务内容，不改变金额；不再生成一条无法删除的“删除历史的历史”。

删除业务记录或项目时说明影响并二次确认，取消后无变化。删除项目同时删除其业务记录与修改历史，不影响月度账单和其他项目。V1 不设回收站；可从此前导出的备份恢复。

## 7. 设置、数据管理与恢复出厂

### 7.1 外观和语言

- 主题有“跟随系统 / 浅色 / 深色”三种明确模式。仅“跟随系统”响应系统变化，手动选择的模式不会被系统覆盖。
- 语言支持“跟随系统 / 简体中文 / 繁體中文 / English”。系统语言不在支持范围时回退 English。
- 所有系统文案、内置分类、默认项目标题、图例、提示框与备忘录入口同步切换；用户自己输入或改写的名称、备注不自动翻译。
- 主题、语言、排序和统计勾选均持久化；重启保持。第一次使用默认跟随系统。

### 7.2 统一备份与恢复

V1 使用一种正式格式：带版本号的 UTF-8 JSON 完整备份，扩展名统一为 `.json`。导出的文件可直接导入本应用，覆盖项目、金额记录、账单、分类、备忘录、修改历史与设置。

流程：

1. 导出：生成一致的数据快照 → 系统文件选择器选择位置 → 写入完成后才提示成功，显示文件名与记录数量。
2. 导入：选择文件 → 校验格式、版本和记录关系 → 展示内容数量与覆盖范围 → 用户确认 → 全部成功后提交。
3. V1 只做“完整恢复并替换”，不做合并导入。相同备份重复恢复不能增加记录。
4. 覆盖前生成应用内临时恢复副本，失败自动回滚；副本生成失败则停止覆盖。设置页可查看或删除该恢复副本，不能将它当作卸载后仍存在的备份。

格式错误、文件损坏、不支持的版本、取消选择或写入失败，均不能破坏原数据，也不能提示成功。旧版文件未经样本校验不承诺兼容。JSON 是明文文件，导出页用一句话说明“包含完整财务数据，请妥善保存”。

参考 Actual Budget 的[完整备份](https://actualbudget.org/docs/backup-restore/backup/)与[交易文件导入](https://actualbudget.org/docs/transactions/importing/)分开处理的思路；本项目的 JSON 协议是自行定义，不声称兼容 Actual。CSV 仅列入后续交换需求，不用它承担完整恢复。

### 7.3 恢复出厂

页面明确说明：清除全部项目数据、账单、备忘录、修改历史和应用内恢复副本，重建默认项目，所有金额归零，主题和语言恢复跟随系统，排序恢复默认。

先提供“导出备份”选项，再要求用户明确确认清空；允许用户选择不备份。用户已导出到外部的文件不会被删除。整个重置必须成功或整体回滚，不能只清空部分表。V1 不包含用户自定义的“出厂金额模板”。

## 8. Android 体验与交付底线

- 详情页响应左右边缘的系统返回手势和系统返回键，返回上一层；普通横向滑动不退出应用。首页根页面返回遵循系统行为，允许离开应用。
- 有键盘或弹层时优先按系统规则关闭；有未保存修改时提供继续编辑、放弃、保存选项。取消返回手势不能丢失内容。
- 适配状态栏、挖孔、安全区域、手势导航区、键盘以及字体放大。目标覆盖 360–480dp 常见手机宽度，320dp 和横屏做溢出检查，关键点击区域至少 48dp。
- 主流程离线可用，进程被系统终止后已保存内容仍在；账务数据保存在应用私有数据库，发布版不记录完整财务内容到日志，不主动上传财务数据。
- 首版不依赖系统云备份，开发时明确配置备份策略；用户自行保存的导出文件承担换机和重装恢复。
- 交付必须包含可安装的 Android 包、安装说明、版本及数据格式说明、实际测试结果；无法真机验证的项目必须写明“未验证”。

**V1 完成标准：功能可用、数据不丢、统计口径一致、备份可完整恢复，且文档 03 的验收场景通过。界面做完不代表软件完成。**
